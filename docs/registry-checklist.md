# Registry and deployment checklist

All 22 formats below can be created in **Admin → Registries** in `hosted`, `proxy`, or `hybrid` mode. **Hosted** means clients can install from local storage without an upstream. It does not always mean the tool has a native publish API. **Proxy** means a read-through cache, not forwarding writes. Each entry describes how to populate the hosted format.

On a new installation the catalogue is seeded **disabled**. On an existing installation create the new instances you want; upgrading does not change your registries. `$R` below stands for the instance URL, e.g. `https://packages.example.org/r/maven`. For private instances use a registry-scoped read token; for uploads use a publish token (usually read + publish for native clients).

- [x] **Alpine APK** (`alpine`) — Point `/etc/apk/repositories` at e.g. `$R/v3.23/main`. PUT the architecture tree with signed `APKINDEX.tar.gz` and `.apk` files.
- [x] **Cargo / Rust** (`cargo`) — Use `index = "sparse+https://host/r/cargo/"` in the Cargo registry definition. Sparse index, rewritten download template and native `cargo publish --registry <name>`. No Git index required.
- [x] **Composer / PHP** (`composer`) — `composer config repositories.depyard composer "$R"`. PUT a prepared Composer v2 repository (`packages.json`, package metadata, dist archives).
- [x] **Conan 1.x and 2** (`conan`) — `conan remote add depyard "$R"`. Legacy v1 snapshots and upload/download URL negotiation; v2 revision discovery, file lists, recipe and binary upload/download. Use the Depyard token as the remote password.
- [x] **Conda** (`conda`) — `conda install --override-channels -c "$R" PACKAGE`. PUT a channel generated by `conda index`, including `noarch/` and the target platform subdirectories.
- [x] **CRAN / R** (`cran`) — `install.packages("pkg", repos="https://host/r/cran")`. PUT `src/contrib/` or the binary tree with indexes generated by `tools::write_PACKAGES`.
- [x] **Debian APT** (`debian`) — Use `$R` as the repository URI with your suite, components and `Signed-By` key. PUT `pool/` and the signed `dists/` tree (or a prepared flat APT repository).
- [x] **Docker / OCI** (`oci`) — Distribution `/v2/`, manifests and indexes, SHA-256 blobs, monolithic and chunked push, pull-through cache with upstream bearer negotiation. Use a **hostname**, not a URL prefix, with `docker login/push/pull`. See below.
- [x] **Git LFS** (`gitlfs`) — `git config lfs.url "$R"`. Basic batch transfer, upload and digest-verified download. For proxying, set the upstream to a repository's LFS endpoint (often `…/repo.git/info/lfs`). Does not host Git refs or implement file locks.
- [x] **Go Modules** (`goproxy`) — `GOPROXY="$R" go mod download`. Import a Go **module-format** zip with authenticated `PUT $R/<module>/@v/<version>.zip`; list, `.mod` and `.info` are derived locally. The Go tool itself has no publish command.
- [x] **Helm** (`helm`) — `helm repo add depyard "$R"`. PUT charts, `.prov` files and an `index.yaml` generated by `helm repo index`. For `helm push` to an OCI registry use `oci` instead.
- [x] **Hugging Face** (`huggingface`) — `HF_ENDPOINT="$R" hf download org/model`. Hub repo info, trees, HEAD/GET, model/dataset/space snapshots. PUT files at `/<id>/resolve/<40-hex-commit>/<file>` and PUT the commit ID as text to `/<id>/refs/main` **last**. Prefix dataset/space paths with `/datasets` or `/spaces`. This is snapshot hosting, not the Git, Xet, inference or Hub commit API.
- [x] **Apache Ivy** (`ivy`) — Use `$R` as the URL resolver root; use matching Ivy and artifact patterns for publish and resolve. Set your own upstream for proxy mode (there is no universal Ivy layout).
- [x] **Maven** (`maven`) — Use `$R` as the repository and `distributionManagement` URL. Maven deploy PUTs POMs, artifacts, metadata and checksums in Maven 2 layout.
- [x] **Nix** (`nix`) — Use `$R` as a substituter with the cache's trusted public key. PUT a binary cache containing `nix-cache-info`, signed `.narinfo` and `nar/` archives; no signing key is stored by Depyard.
- [x] **npm** (`npm`) — `npm install --registry "$R/"`; native `npm publish`, scoped packages, packuments and tarballs (existing implementation).
- [x] **NuGet** (`nuget`) — `dotnet nuget add source "$R/v3/index.json"`. V3 service discovery, flat-container restore and `dotnet nuget push … --api-key "$TOKEN"`. Configure the upstream **service index URL**. Does not advertise a search or symbol server.
- [x] **Arch Linux / Pacman** (`pacman`) — Set `Server = https://host/r/pacman/$repo/os/$arch` in `pacman.conf`. PUT the `repo-add` databases, packages and signatures.
- [x] **Pub / Dart and Flutter** (`pub`) — `PUB_HOSTED_URL="$R" dart pub get`; native Pub v2 and `dart pub publish` (existing implementation).
- [x] **PyPI / Python** (`pypi`) — `pip install --index-url "$R/simple/" PACKAGE`; Twine uploads to `$R/legacy/` (existing implementation).
- [x] **RPM / YUM / DNF** (`rpm`) — Set `baseurl` to the distribution directory under `$R`. PUT RPMs, `createrepo_c` metadata under `repodata/`, and signatures.
- [x] **RubyGems** (`rubygems`) — `gem install --clear-sources --source "$R" GEM`. PUT a prepared gem repository (`gem generate_index`) and/or a Bundler compact index with `gems/` archives. Not a RubyGems.org account or `gem push` API.

Flutter **SDK storage** (`flutter`) remains a separate proxy-only type; it is not the Dart/Flutter Pub package registry.

## Operating the repositories

- [x] **Hosted + proxy:** choose `hybrid` for local objects with upstream fallback. In file-layout repositories an uploaded index shadows that upstream file; indexes are **not merged or re-signed**. Generate a combined index yourself or configure separate remotes. Upload dependencies, packages and signatures before the index that makes them discoverable.
- [x] **Bind host + port:** `BIND_HOST` and `BIND_PORT` select the public listener. The standalone backend defaults to `0.0.0.0:8080`; legacy `LISTEN_ADDR` takes precedence. In Compose the variables select the published address/port of NGINX, **not** the container-internal backend socket. Without `BIND_PORT`, Compose uses `HTTP_PORT` (default 80; installer default 8080).
- [x] **HTTPS + certificates:** configure both `TLS_CERT_FILE` (PEM leaf + intermediate chain) and `TLS_KEY_FILE` (matching unencrypted PEM private key). Both empty means HTTP. An incomplete, unreadable or invalid pair fails startup instead of falling back to HTTP. See the examples below.
- [x] **Architecture:** protocol-specific adapters depend on the registry contract and shared services, not MongoDB or the HTTP router. File-tree formats reuse one repository adapter. Registration and first-install seeding are composed in `backend/cmd/server`; the admin UI reads capabilities and defaults from the API.

### Prepared trees

For a repository whose native format is a directory tree, a publish token and HTTP PUT are enough. For example, after generating a Helm repository locally:

```sh
R=https://packages.example.org/r/helm
curl --fail -H "Authorization: Bearer $TOKEN" -T hello-1.0.0.tgz "$R/hello-1.0.0.tgz"
curl --fail -H "Authorization: Bearer $TOKEN" -T index.yaml "$R/index.yaml"
helm repo add internal "$R"
helm pull internal/hello
```

Use relative artifact URLs when building a relocatable index. The Composer and Helm adapters rebase same-upstream links and can mirror GitHub release/zipball archives found in upstream metadata. Unrecognized external sources remain client-side links; do not assume a third-party feed is fully usable offline. For air-gapped installs, host the entire tree including archives. For signed OS repositories keep client verification enabled and distribute the public key separately.

### OCI routing and auth

Docker discovers `https://HOST[:PORT]/v2/`. Enable an OCI instance and either mark it **default** with root compatibility routing enabled or configure a dedicated hostname pointing at Depyard. NGINX forwards `/v2/` to the backend; `/r/<slug>/v2/` also works for API clients. `docker login HOST` uses Basic auth: supply a username and use the **Depyard token** as the password. For the Docker Hub upstream use `library/alpine` rather than the Docker Hub shorthand `alpine`. Credentials for private upstreams are configured separately on the instance. The implementation covers SHA-256 pulls/pushes, not registry administration, referrer discovery or deletion via the Distribution API.

### Bind and TLS examples

**Standalone backend** (the Go service, without the web UI):

```sh
cd backend
BIND_HOST=127.0.0.1 BIND_PORT=8443 \
TLS_CERT_FILE=/etc/depyard/fullchain.pem TLS_KEY_FILE=/etc/depyard/privkey.pem \
STORAGE_BACKEND=memory go run ./cmd/server
```

Use `STORAGE_BACKEND=mongo` and a persistent data directory for production. The standalone server reads its process environment; it doesn't source `.env` itself. Use an unbracketed IPv6 address such as `::1` for `BIND_HOST`.

**Compose / installer:** copy `.env.example` to `.env` for a source checkout, or edit the installer's `.env`. For example:

```dotenv
BIND_HOST=0.0.0.0
BIND_PORT=443
PUBLIC_BASE_URL=https://packages.example.org
TLS_CERT_DIR=/srv/depyard/certs
TLS_CERT_FILE=/run/depyard/tls/fullchain.pem
TLS_KEY_FILE=/run/depyard/tls/privkey.pem
```

`TLS_CERT_DIR` is on the **host**. It is mounted read-only at `/run/depyard/tls` inside NGINX; both PEMs (including any symlink targets) must be accessible there. Keep private keys outside Git/build contexts and restrict host permissions. Recreate the gateway after changing its environment (`docker compose up -d --build` for a source install); restart it after renewing the PEMs. Clients must trust the issuing CA. The selected public port now speaks **only HTTPS**, including the SPA, REST API and registry endpoints. The backend remains HTTP on the private Compose network. For TLS termination at an existing reverse proxy instead, leave both TLS variables empty and configure the public HTTPS origin. On an existing installation also check **Admin → Settings → Public Base URL**: persisted settings take precedence over the bootstrap environment.

For a **local TLS test only**, you can make a one-day certificate and verify it explicitly. Use a CA-issued certificate for a shared deployment.

```sh
mkdir -p certs
(umask 077; openssl req -x509 -newkey rsa:2048 -nodes -days 1 \
  -subj /CN=localhost -addext 'subjectAltName=DNS:localhost,IP:127.0.0.1' \
  -keyout certs/privkey.pem -out certs/fullchain.pem)
# Use the Compose settings above with TLS_CERT_DIR=./certs, BIND_HOST=127.0.0.1,
# BIND_PORT=8443 and PUBLIC_BASE_URL=https://localhost:8443. Then:
docker compose up -d --build
curl --cacert certs/fullchain.pem https://localhost:8443/healthz
```

## Verification

- `cd backend && go test -race ./...` covers the registry catalogue, hosted reads/writes, local fake upstreams, cache reuse, authorization, quotas, routing and TLS. It uses the Go toolchain to download an imported module.
- To run the optional native-client tests, set `DEPYARD_TEST_APT_GET`, `DEPYARD_TEST_CONAN1`, `DEPYARD_TEST_CONAN2` or `DEPYARD_TEST_HF_PYTHON` to the corresponding executable before running `go test -count=1 ./cmd/server` from `backend/`. APT builds a `.deb` using `dpkg-deb`, updates a temporary source and downloads the package without installing it. Each Conan client publishes and downloads a recipe and binary. The Python interpreter needs `huggingface_hub` for the snapshot download test. All four use local servers.
- `bash tests/installer_test.sh` checks install and upgrade behaviour without a Docker daemon. CI also validates HTTP and TLS configurations in the built NGINX image.
